# Release-ready development and compatible batch release

Ordinary development: work on local/remote branches without an open PR for zero Main-targeted PR workflow triggers. If collaboration requires a PR, open it as draft. Draft PRs targeting Main defer expensive acceptance and run only the lightweight Pages typecheck/withheld aggregate. The aggregate is deliberately non-success on drafts: skipped jobs do not authorize merge. For an existing ready PR, keep it ready: consolidate and test locally, incorporate current Main once, then push once. Never toggle draft/ready merely to update or reconcile an existing ready PR. Use `node scripts/ci/ready-pr-update.mjs PR_NUMBER` for a read-only plan, then repeat with `--apply` for one checked non-force push. Fetch the current Main and PR commits locally first; a stale or non-fast-forward candidate is rejected. An unchanged head is a no-op. A ready PR push triggers full applicable acceptance. Existing ws5 integration branches and non-Main PR behavior remain unchanged.

All 16 Main-capable PR workflow definitions retain original branches, paths, jobs, permissions, production/manual triggers and full ready acceptance; 2 non-Main Phase 7 workflows remain untouched. No new workflow definition. The deduplication removes only duplicate browser selections already covered by mandatory unfiltered suites. Historical/skipped workflow rows may remain visible. Do not use skip-ci, force-push Main, skip security, or treat a skipped workflow as PASS.

Parallel work is welcome. Independently accepted compatible features may be combined into one exact-tree release PR without arbitrary feature-count limits. Check changed paths AND shared behavior/API/SQL/Office/configuration contracts. Preserve source histories, owner work, and cumulative full applicable tests. Avoid unrelated failure holding safe independent work. Coordinate short protected Main merge operations and production publication; keep existing production operational. Confirm all applicable exact-head successful workflow evidence, independently restore-test and back up current Main, refresh base/head, protected merge, exact Main SQL/Office acceptance, real production URL/SHA and live verification. Eligible unchanged trees may reuse verified artifacts only under the existing fail-closed provenance policy.

Existing open PRs inherit changed workflow definitions when reconciled with Main; coordinate owners, never rebase or overwrite active work without checking. Record actual runner allocations, queue and comparable p50/p95 ready-to-live times; fewer visible rows do not prove speed. No arbitrary acceleration guarantees. Existing mandatory release protections and application source unchanged.

Draft/ready concurrency isolation: workflows that cancel superseded PR runs use a distinct `-draft` suffix only for deferred ordinary draft PR events targeting Main. A delayed draft event cannot cancel or replace a queued/running full acceptance event. Existing full, WS5, non-Main, Main push and manual concurrency identities and cancellation conditions remain unchanged. A draft/skip result is never release evidence; confirm the exact ready event and all required jobs. The Pages preflight runs the concurrency regression contract.

Release queue discipline: converting a PR to draft does not change source and no longer triggers these 16 Main-capable workflows. GitHub draft merge restrictions, existing draft eligibility guards, required named gates and exact-source validation remain unchanged. Open/synchronize/reopen/ready_for_review and existing Main/manual/path triggers are retained. Keep PR status stable; prepare changes locally in one batch, mark ready once when release capacity and dependencies are available, and do not reconcile independent branches merely because Main advanced. Reconcile the next eligible integrated slice once against current Main after the preceding production gate completes. Never cancel a useful current-head check, weaken mandatory acceptance, or treat a skipped draft check as release evidence. Historical runs are retained.
